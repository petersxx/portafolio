1. CONCEPTO DE LA PÁGINA
----------------------------------------------------------------
Sitio web de "Main Technologies", una empresa (ficticia/personal)
de desarrollo de software. Funciona como landing page / portafolio
corporativo de una sola página (one-pager) con las siguientes
secciones, en este orden:

  - Inicio (hero): título, bajada, botones "Ver proyectos" y
    "Hablemos", y una caja de CD que crece girando con el scroll.
    El hero vive dentro de un "escenario" alto: mientras se
    recorre, la pantalla queda fija y el CD va creciendo desde su
    lugar hasta ocupar toda la pantalla, girando sobre su propio
    eje y cambiando entre sus 3 fotos (frente, en ángulo y dorso)
    con un giro tipo moneda. El texto, el halo y los destellos se
    apagan mientras el CD toma la pantalla; cuando termina el
    escenario, la caja se despega y entra el resto de la
    información (marquee, Nosotros, etc.). Con inercia.
  - Marquee: cinta animada con palabras clave de los servicios
    (Diseño web, Software a medida, E-commerce, etc.).
  - Nosotros: texto de presentación + estadísticas animadas
    (proyectos, años, tecnologías).
  - Servicios: carrusel con 6 tarjetas (Desarrollo web, Software a
    medida, E-commerce, Aplicaciones web, Diseño UI/UX,
    Automatización e integraciones) + "Tecnologías que usamos".
    Las dos son cintas continuas (igual en técnica al marquee de
    palabras clave del hero): se deslizan solas todo el tiempo, sin
    flechas, sin puntos y sin paradas. Las tarjetas van hacia la
    izquierda y las tecnologías hacia la derecha, en sentidos
    opuestos. El bucle es perfecto porque en realidad hay dos
    copias idénticas del bloque, una detrás de la otra, y la
    animación recorre exactamente el ancho de una copia antes de
    reiniciarse. Se pausan al pasar el mouse por encima o al
    enfocar con el teclado, y no se animan si el sistema tiene
    activado "reducir movimiento".
  - Proyectos: tarjetas con 3 casos reales de clientes (RENOVA
    Constructora, Solar Guaraní, JAKAY'U), cada una enlaza al sitio
    real del cliente.
  - Contacto: formulario (nombre, email, mensaje) que NO envía
    email — arma un mensaje y abre WhatsApp Web/App con el texto
    precargado.
  - Footer: copyright dinámico (año actual) y link a GitHub.

Estética "chromecore": fondo animado tipo cromo líquido (WebGL),
tipografía Unbounded/Space Grotesk/Space Mono, modo claro/oscuro
("ice chrome" / "black chrome") con toggle persistido en
localStorage, y estrellas/destellos decorativos en SVG.

2. STACK TÉCNICO
----------------------------------------------------------------
  - HTML5 semántico, un solo archivo: index.html
  - CSS3 puro con variables, grid y tema claro/oscuro: css/styles.css
  - JavaScript vanilla, SIN framework ni build (no hay
    package.json ni bundler):
      · js/main.js   → menú, tema, contador de stats, scroll-reveal,
                        nav activo, envío del form a WhatsApp,
                        cambio de cuadros del CD del hero según
                        el scroll
                        (el carrusel de servicios es puro CSS, sin
                        lógica en JS)
      · js/chrome.js → shader WebGL del fondo animado
  - Imágenes del hero: assets/img/cd-1.webp, cd-2.webp, cd-3.webp
    (fondo recortado, transparentes, 1040×1040)
  - Despliegue: Vercel (hay proyecto vinculado, ver .vercel/) y
    también preparado para GitHub Pages (branch main / root)

No hay backend, base de datos ni build step: es un sitio 100%
estático que puede abrirse con cualquier servidor simple (se
recomienda `python3 -m http.server 8000`).

4. LO QUE FALTA / PENDIENTE
----------------------------------------------------------------
Cosas identificadas revisando el código que probablemente valga
la pena resolver o decidir:

  - Datos de ejemplo/placeholder en "Nosotros": las estadísticas
    (15 proyectos, 3 años, 12 tecnologías) están hardcodeadas en
    js/main.js (STATS) — confirmar que sean los números reales.
  - Sección "Proyectos" tiene solo 3 casos; si hay más trabajos de
    clientes, faltaría cargarlos.
  - El comentario en js/main.js ("Cambiá este email...") quedó
    desactualizado: ya no se envía por email, se envía por
    WhatsApp — conviene limpiar el comentario.
  - No hay meta tags de Open Graph / Twitter Card (og:image,
    og:title, etc.) para que se vea bien al compartir el link en
    redes o WhatsApp.
  - No hay favicon como archivo real: se usa un SVG inline como
    data URI. Podría convenir un favicon.ico/png tradicional para
    mejor compatibilidad.
  - No hay analítica (Google Analytics, Plausible, Vercel
    Analytics, etc.) para medir visitas.
  - No hay política de privacidad ni aviso legal, algo esperable
    en un sitio de empresa con formulario de contacto.
  - El formulario de contacto no valida ni guarda nada del lado
    servidor: si el usuario no tiene WhatsApp o falla el popup,
    no hay fallback (ej. mailto: o servicio de email tipo
    Formspree).
  - No se ve dominio propio configurado todavía (aparece
    desplegado en Vercel con nombre de proyecto "portafolio"); si
    la marca es "Main Technologies", podría convenir un dominio
    acorde.
  - No hay tests, ni linter, ni CI configurado (razonable para un
    sitio estático de este tamaño, pero queda anotado).
  - README.md sigue mencionando GitHub Pages como opción de
    publicación, pero el despliegue real actual parece ser Vercel
    (existe .vercel/project.json) — podría actualizarse el README
    para reflejar el método de deploy vigente.
  - El logo/marca es solo texto ("Main Technologies") con efecto
    "chrome-text"; no hay isotipo/logo gráfico propio más allá de
    la estrella genérica.

  [2026-09-15] Sombra propia en las tarjetas de Servicios
    ESTADO FINAL (lo que quedó):
    - Cada tarjeta de Servicios tiene una sombra permanente (no
      solo al pasar el mouse) que cambia según el tema, con dos
      variables CSS nuevas: --card-glow y --card-bg.
    - Modo oscuro: sombra oscura de apoyo + un halo claro
      azulado, para que la tarjeta resalte contra el fondo oscuro.
    - Modo claro: una sola sombra oscura, suave y difusa.
    - Las tarjetas NO llevan backdrop-filter (ver punto 3 abajo);
      para compensar, su fondo (--card-bg) es más opaco que el del
      resto de los paneles .glass.
    - El borde lo sigue dando el pseudo-elemento .glass::before
      del propio sitio; no se agrega ninguno extra.

    QUÉ NO FUNCIONÓ (para no repetirlo):
    - Se intentó "hacerla resaltar" apilando efectos: un anillo
      sólido de 1.5px hecho con box-shadow, más una neblina de
      color, más un halo blanco. Resultado: se veía barato, porque
      ese anillo duro competía con el borde degradado que las
      tarjetas ya traen de .glass::before, y desentonaba con el
      resto de las tarjetas del sitio (Proyectos, Nosotros), que
      usan una sola sombra suave. Lección: para que resalte,
      seguir el lenguaje visual del sitio en vez de sumar capas.
    - Se corrigió una banda rectangular con bordes rectos que se
      veía alrededor de las tarjetas y parecía una sombra sólida.
      Fueron TRES causas distintas, encontradas una tras otra:
        1) El carrusel usaba overflow-x: hidden, y cuando un eje
           está en "hidden" el navegador convierte el otro de
           "visible" a "auto", que también recorta. Se cambió a
           overflow-x: clip, que sí deja el eje vertical libre.
        2) La máscara del degradado lateral (mask-image) recorta
           todo lo pintado fuera de la caja del carrusel. Se le
           agregó padding vertical de 60px, cancelado con margen
           negativo, para agrandar esa caja sin mover el layout
           (el espaciado alrededor quedó idéntico).
        3) La causa principal: las tarjetas heredaban de .glass el
           backdrop-filter (desenfoque del fondo). Como la cinta
           se anima con transform, eso crea un "backdrop root", y
           el desenfoque se pinta como un rectángulo con bordes
           duros que abarca toda esa caja. Eso era la banda. El
           transform es imprescindible para la animación, así que
           se desactivó el backdrop-filter solo en .skill-card
           (el resto de los paneles .glass lo conservan).
      Cómo se diagnosticó: ocultando las tarjetas la banda
      desaparecía, lo que descartó al contenedor como causa.
    - El carrusel solo recorta el desborde horizontal (donde está
      el empalme del bucle); el vertical quedó abierto para que el
      brillo no se corte contra el borde del carrusel.
    - Archivos: css/styles.css, DOCUMENTACION.txt
